## 1. 产品目标与边界

GoFlow 是 Windows 本地通用智能体框架。开发/脚本、运维、安全是首批可替换资源包，不是核心中的固定业务分支。用户通过添加 Agent、Skill、Workflow、Kit、模板、验证资源及必要的外部 MCP 服务扩展领域，不需要修改核心的领域名称列表。

已有工具足够时只需新增资源；缺失执行能力时可开发或配置外部 MCP 适配器，不能承诺 YAML 自动创造新工具。资源声明不能授予权限，执行仍受用户授权、目标边界、超时、数据保护和审计控制。

此前机制回归没有新增付费模型任务。2026-10-25 按继续推进剩余验收的要求，已使用配置中的供应商和模型开展独立开发工作区的真实验收；真实结果与失败记录保留。仍不自动连接真实远程主机、扫描、向外部通道投递或推送 GitHub，不清理用户数据，不改变博客工作区。不得以模拟响应或框架补写产物冒充模型实际交付。

## 2. 核心与资源分工

| 核心能力 | 由资源声明的领域行为 |
| --- | --- |
| 模型与工具调用、任务恢复、事件记录 | 角色、方法、模型路由、工具组合 |
| 图执行、重试、审批和依赖检查 | 领域流程、任务步骤、恢复分支 |
| 安全目标、密钥引用、边界强制 | 所需能力及授权范围（不等于获得授权） |
| 产物与证据持久化、结构校验 | 报告结构、交付模板、专业验证 |
| 定时执行与通用通知通道 | 触发条件、事件内容及接收配置 |
| 联网搜索、抓取、来源与时效元数据、缓存控制 | 官方文档优先、版本适用性、交叉核验和引用规则 |

资源包沿用现有 Kit，不引入第二套包管理。新增契约必须可版本化、可校验、可导出，旧资源维持可解释的兼容路径。运行保存资源身份；API 拒绝修改正在运行任务引用的资源，暂停后恢复发现已知配置版本变化则返回冲突。这不是外部程序、凭据或环境的完整快照，也不能阻止绕过 API 的直接文件改动。
