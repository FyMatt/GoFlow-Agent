# GoFlow V3.1 复杂任务工程验收基线

本基线用于回答一个问题：GoFlow 是否能在真实约束下持续完成复杂任务，而不只是让固定小夹具跑通。

## 1. 复杂任务定义

任务至少满足以下四项中的三项，才进入复杂工作流：

- 跨三个以上模块、服务、主机、来源集合或文档类型。
- 同时要求多个可使用产物，例如源码、测试、发布包、报告和可编辑文档。
- 包含审批、备份、迁移、回滚、恢复、授权范围或敏感数据边界。
- 包含两类以上独立验证，例如测试、构建、静态检查、浏览器复核、来源交叉核验或格式校验。

仅仅出现“复杂”“完整实现”或“高质量”等词语，不构成复杂任务证据。能够用一次读取、一次修改和一次测试完成的请求仍按简单任务执行。

## 2. 验收规模

- 开发、网安和平台类夹具必须包含至少 3 个真实相互依赖模块，并覆盖持久化、并发、协议、页面或远程目标中的至少 3 类边界。
- 文件数量只作为规模观察值，不作为通过条件。未被构建、运行、索引、迁移或验证消费的填充文件不得计入复杂度。
- 预期修改范围为 6 至 30 个文件；如果更小的正确修改可以解决问题，不得为了达到数量而制造无关变更。
- 每个任务包含公开验收条件和独立隐藏验收条件。
- 每个复杂任务至少注入一次可恢复失败，例如 Provider 暂时失败、验证失败、应用进程终止、远程目标失败或文档转换失败。
- 每个任务使用相同干净基线连续执行三次，任意一次硬失败后重新开始该领域计数。
- 隐藏验收由独立进程在智能体停止后安装和执行，任务提示、工作区、模型上下文和工具输出均不得泄露隐藏条件。
- 夹具必须包含至少一个会诱导局部修补但不能解决根因的表面症状，用于检查系统是否完成依赖分析和回归验证。

## 3. 六组真实任务

### 3.1 仓库级软件交付

输入仓库包含 API、持久化、缓存、命令行和浏览器页面。任务要求迁移配置版本、实现并发安全的 TTL 行为、保持旧配置兼容、修改页面状态，并生成升级说明。

必须产出源码 Diff、迁移实现、回归测试、构建结果、静态检查、浏览器复核、升级说明和回滚办法。隐藏测试检查并发、过期状态、旧版本升级、重启恢复和未修改模块。

### 3.2 防御性安全工程

输入为明确授权的本地多模块应用，包含认证、授权、输入校验、文件边界和依赖风险。任务先只读审计，审批后修复有证据支持的问题，再独立复测。

必须产出授权范围、发现与证据映射、最小修复、公开和隐藏回归、未修复项、复测报告和统一安全交付。主动探测只能进入单独的受控红队工作流。

### 3.3 多目标网络运维

输入为至少五个授权测试目标或等价的原生测试进程。任务要求并行只读诊断、金丝雀变更、分批发布、健康检查、第三批次故障注入、停止扩散和精确回滚。

必须产出目标清单、变更前后状态、审批、备份、逐目标结果、失败边界、回滚结果和最终运行手册。失败目标不得导致已经验证成功且无需回滚的目标被重复执行。

### 3.4 互联网资料核验

输入主题至少包含 15 个候选来源，其中包括重复转载、过期页面、同域来源和相互冲突的官方或原始材料。

必须产出来源快照、去重结果、原子事实映射、冲突裁决、无法确认项、完整 URL、发布日期、访问时间，以及内容一致的 Markdown、JSON 和 CSV。隐藏验收会删除一个来源或改变时间边界，系统必须重新裁决而不是复用过期结论。

### 3.5 Office/WPS 组合交付

输入包含带页眉页脚、目录、表格、样式和母版的 DOCX/PPTX 模板，以及 XLSX 数据和书面修改要求。

必须完成读取、基于模板生成、保留格式精确修改、批量修改原子失败保护、数据合并、公式与筛选校验、PDF 导出和逐页预览。未指定的模板内容、母版、公式和固定声明必须保持不变。

### 3.6 跨领域统一交付

输入同时包含软件缺陷、安全发现、部署要求和正式报告要求。系统只选择必要领域，领域结果通过各自质量门后，才生成一份统一交付和正式文档。

必须证明分支选择正确、共享上下文去重、领域失败不会被其他分支掩盖、审批范围不串用、最终报告中的每个结论都能回到真实产物或验证证据。

## 4. 流程硬门

复杂任务必须按以下状态推进：

```text
需求编译 -> 仓库/目标建图 -> 变更分片 -> 风险与审批
-> 分片实施 -> 集成验证 -> 独立审查 -> 有界返修
-> 最终复测 -> 写回 -> 统一交付
```

- 需求编译必须形成目标、范围、限制、交付物、验收条件和停止条件。
- 只读探索可以批量并行，写操作必须按依赖顺序执行。
- 每个变更分片都有输入哈希、影响文件、前置条件和局部验证。
- 已通过且输入哈希未变化的分片不得重复执行。
- 返修只能处理明确阻断项，最多进行一个有界返修周期；仍失败则交付为阻断，不能无限循环。
- 最终成功只能由真实文件、Diff、命令、来源、文档结构或浏览器证据决定。

## 5. 工具健壮性门

- 文件搜索优先使用增量索引和仓库地图；索引无结果时才进行受限全文扫描。
- 同一文件哈希不得重复注入完整内容；后续阶段使用摘要、符号和产物引用。
- 写入必须使用 SHA-256 前置条件、原子提交和可恢复日志。
- 命令必须以参数数组执行，不允许模型拼接 Shell；超时和取消终止整个进程树。
- 测试、构建和静态检查按唯一命令指纹去重；已经通过且输入未变化时复用证据。
- 网络和资料工具保留 URL、时间、哈希、重定向和来源域；缓存必须受截止日期和内容哈希约束。
- Office 工具必须保留源文件哈希、备份、修改清单、结构校验、转换器和逐页预览证据。

## 6. 质量与效率指标

每轮同时满足以下条件才通过：

- 需求覆盖率 100%，没有越出允许范围的 Diff。
- 所有硬验收命令通过；基础设施限制必须明确标记且不能掩盖功能失败。
- 产物可以运行、安装、打开或直接提交。
- 没有模型自评、模拟日志、伪造来源或不存在的文件。
- 无产物模型调用占比低于 5%。
- 相同参数的重复工具调用为 0；相同文件哈希的重复完整读取为 0。
- 复杂任务失败恢复后，不重复已经完成的副作用操作。
- 每个领域连续三次通过，且每次独立质量评分不低于 80/100。

### 6.1 独立质量评分

评分只能在全部硬门通过后进行；任一硬门失败时总分为 0，不允许用文档完整或模型解释抵消功能失败。

| 维度 | 分值 | 独立证据 |
| --- | ---: | --- |
| 功能正确性 | 35 | 公开测试、隐藏测试、真实运行、边界和失败路径 |
| 工程完整性 | 20 | 构建、静态检查、迁移、兼容、恢复、发布或可打开产物 |
| 安全与范围控制 | 15 | 授权、最小权限、敏感信息、路径边界、审批和越权 Diff |
| 可维护性 | 10 | 模块边界、重复实现、错误处理、测试质量和变更可读性 |
| 效率 | 10 | Token、工具耗时、重复调用、缓存命中、并行与失败恢复 |
| 交付可用性 | 10 | 使用说明、证据映射、预览、回滚、风险和最终产物 |

评分器必须输出每个扣分项对应的文件、命令、证据或指标，不接受“质量良好”一类模型自评。代码和安全领域至少执行一组属性、竞态、模糊或恶意输入验证；页面和文档领域必须包含真实渲染检查。

### 6.2 防止针对夹具投机

- 禁止根据测试文件名、任务编号或隐藏夹具路径写特判。
- 禁止删除、跳过、放宽或重写验收测试来获得通过。
- 禁止以硬编码固定输出替代真实数据流、状态迁移、来源核验或模板修改。
- 独立评分器检查工作区 Diff、测试变更、未跟踪文件和生成物来源；发现投机行为直接判为失败。
- 每个领域至少维护两个数据变体和一个故障变体，连续三轮随机选择但记录随机种子。

## 7. 分阶段验收策略

正式 18 轮矩阵之前按以下顺序推进，避免用昂贵 Provider 调用反复发现基础设施问题：

1. 夹具自证：未修复基线必须失败，参考实现必须通过，隐藏门确实能识别表面修补和越界修改。
2. 工具压力门：文件、命令、网页、SSH、Office、暂存写回和恢复分别通过属性、并发、超时、取消、损坏输入和边界测试。
3. 单领域首轮：六类任务各运行一次，逐项分析任务契约、工具轨迹、Diff、验证和最终产物，不追求连续次数。
4. 失败驱动加固：只能修复可复现的框架、工具、资源或工作流根因；不得把特定答案写进提示词或 Skill。
5. 连续验收：每个领域从同一干净基线连续通过三次，失败后该领域重新从第一轮计数。
6. 产品验收：任务页能用中文显示契约、当前分片、阻断、审批、验证和产物，并完成 PC 桌面、浅色/深色截图复核。
7. 发布验收：Windows amd64 构建、安装、升级、恢复、原生隔离、清理和证据归档全部通过。

## 8. 证据保留

正式验收结果不得只写入 `.artifacts`、`.tmp` 或构建缓存。每轮必须在用户选择的验收工作区中保留：

```text
交付证据/<领域>/<任务编号>/<轮次>/
  request.txt
  task-contract.json
  timeline.json
  approvals.json
  tool-summary.json
  diff.patch
  verification.json
  quality-score.json
  deliverables/
  report.json
```

缓存可以清理；上述验收证据只能由用户明确删除。报告必须记录 Provider、模型、任务 ID、工作区基线哈希、开始与结束时间、Token、工具耗时、失败恢复、最终产物哈希和独立复测结果，但不得记录 API Key、私钥或敏感文件正文。
